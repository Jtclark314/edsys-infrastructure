# 9950x isolated 3D workstation

Scope: approved installation/workspace/software qualification steps 1–3, followed
by the owner-confirmed Ender-3 V3 KE 0.4 mm/Zyltech pink PLA software baseline.
Stock-LAN connection testing and local uncalibrated slicing pass; physical
calibration, delivery and print approval remain pending. No extra plugin platform
or AI-generation service is commissioned. Owning current-state guide: EdSys-Master
`docs/9950X_3D_PRINTING.md`.

## Source and installed layout

`releases.json` pins official portable download URLs and SHA256 values.
`cadquery.lock` and `trimesh.lock` pin Python dependencies with required hashes.
`apps.json` maps application names to versioned relative executable paths.
Runtime belongs under `/mnt/ai-store/3d-printing`, not this repository.

Installed system footprint is limited to:

- `/usr/local/libexec/edsys-3d/edsys_3d.py` and `/usr/local/bin/edsys-3d`;
- root-owned `/etc/edsys-3d/{storage,apps}.json`;
- the user's `edsys-3d-*.desktop` menu entries and `Desktop/3D Printing` folder;
- five durable-workspace entries in the existing encrypted backup include list.

No system Python package, NVIDIA driver, BIOS/security setting, existing service,
shell initialization or unrelated package is changed. GUI AppImages are extracted
to versioned directories rather than requiring FUSE at launch. Blender uses its
official tarball. Existing Ubuntu X11/Mesa/GTK libraries and Xvfb are reused.
All seven tools remain independently removable.

## Deployment and qualification order

1. Verify backup/offsite/restore evidence, exact writable ext4 AI Store identity,
   NVIDIA, service probes and free space. Preserve the disconnected old system
   disk through the separate migration retention gate (at least 2026-09-11).
2. Create the documented workspace and a private root-owned `storage.json` from
   the example, using the **live verified UUID**, never a `/dev/nvme*` name.
   Install the guard and root-owned `apps.json` before any launcher or tool use.
3. Create the CadQuery environment with existing `uv venv --python
   /usr/bin/python3`; synchronize `cadquery.lock` using `uv pip sync
   --python ENV/bin/python --require-hashes`. Point `UV_CACHE_DIR` and temporary
   paths to the verified workspace. Replace the venv's `bin/python` symlink with
   a copy of `/usr/bin/python3.12` so executable resolution remains inside the
   guard. System standard-library use remains intentional; third-party packages
   stay isolated. Do not activate globally or modify shell startup.
4. Run `qualification/cadquery_sample.py` through `edsys-3d cadquery` with the
   example-project directory argument; require solid/volume and STEP reopening.
5. Run `python3 install_portable.py freecad`. Copy/run the FreeCAD macro in an
   isolated Xvfb session. Require native feature history and STEP geometry checks.
6. Install Blender with the same helper, then run the Blender sample through
   `edsys-3d blender --background --factory-startup --python-exit-code 1 --python
   SAMPLE`. Require native reopening, editable modifier, millimeter STL and CPU
   preview. Inspect the preview. GPU rendering is a separate qualification gate. The optional
   `qualification/blender_gpu.py` requires at least 2 GiB free VRAM and tests
   only a 64x64/four-sample CUDA render without changing saved defaults; this
   small gate passed, but large scenes and GUI acceleration are not qualified.
7. Install OpenSCAD, compile the SCAD master to STL, import/export that STL again,
   and generate a preview using Xvfb. Preserve the SCAD as the editable master.
8. Create/synchronize the separate Trimesh environment from `trimesh.lock`, with
   the same interpreter-copy rule. Run its sample to inspect all four meshes and
   round-trip each through PLY. Do not merge this environment with CadQuery.
9. Install OrcaSlicer and test it before proceeding to Creality Print. Use the
   fully resolved, explicitly **qualification-only** bundled generic profiles
   generated by `qualification/slicer_profiles.py`. Feed machine/process with
   `--load-settings`, filament with `--load-filaments`, and export an unsliced
   3MF from the CadQuery STL. Reopen with `--info` and then through the GUI.
10. Repeat the project export/reopen and native GUI checks in Creality Print.
    Choose Professional mode, skip cloud login and printer connection. Do not
    enable AI Edition Beta, install networking plugins or claim stock-printer
    delivery qualification from an offline generic sample.
11. Install the eight guarded launchers using `install_launchers.py`; run unit,
    missing-storage, final service/backup and source-of-truth closeout checks.

## Guard contract

The launcher validates the exact mount point, UUID, filesystem type, writable
state, independent device and workspace containment **before creating anything
or looking up an application**. Symlink escapes are refused. Its cwd stays on
AI Store, preventing ordinary unmount while active. HOME, XDG configuration/data,
cache and temporary paths are application-isolated on AI Store; the working
directory is the app temporary directory so incidental CLI logs cannot clutter
projects. Explicitly save editable work into the selected project folder; system/shell
Python and Qt injection variables are cleared. Core dumps are disabled.

The default GUI path is X11 with software Mesa, four CPU/LLVM threads and saved
CPU Blender rendering. `--gpu` is an explicit qualification switch, not an
accepted acceleration profile. Never disable a production service to make room
for a test. This launch-time guard is not a sandbox against a user deliberately
running extracted binaries, selecting arbitrary absolute save paths, or forcing
a lazy unmount/removing live hardware. Do not do those things.

The negative storage test overlays only `/mnt/ai-store` in a **private mount
namespace** and verifies refusal plus no fallback workspace. It does not unmount
or alter the production AI Store. Unit tests also reject wrong UUID, mount,
filesystem, read-only state and symlink traversal.

## Known qualification lessons

- An unconfigured Orca CLI export produced a 3MF whose CLI reopen crashed. Do
  not use empty/default profile state for automation. The qualified generic
  project reopens correctly in both CLI and GUI.
- Orca CLI compatibility uses the inherited system profile identity, not a
  renamed user label. The test resolver keeps that identity while supplying all
  inherited values and labeling outputs as unapproved software tests.
- FreeCAD's test macro closes its unsaved exchange document before exiting so
  an unattended save prompt cannot masquerade as an application hang.
- Creality CLI thumbnail generation still attempts an unavailable Wayland
  display even with explicit X11 variables. Export/reopen geometry and native
  GUI rendering pass; CLI thumbnails are not qualified. Use the GUI or separate
  Blender/OpenSCAD previews rather than treating a missing thumbnail as a mesh
  failure.
- Generated diagnostics remain in `temporary/` or the private maintenance
  folder. The project `approved/` and `print-results/` remain empty.

## Backup and rollback

Back up `projects`, `printers`, `materials`, `library`, and
`environments/user-data` through encrypted Restic. Portable apps, dependency
environments, caches, temporary files and installers are replaceable and excluded
from that addition. The source repository and `/etc/edsys-3d` are already in
existing include roots. Generated STL, STEP, native files and private app
configuration do not belong in Git or default RAG.

Rollback is selective: close only these applications, remove the eight
`edsys-3d-*` launchers and guard link/helper/config, and quarantine the specific
version directories. Retain projects/profiles and the release/hash locks.
Remove only the five added backup include lines if intentionally retiring the
workspace; never replace the entire include file. Existing services, RDP,
Sunshine and system Python require no rollback because they were not changed.
Reinstall from hashes and restore durable files into a separate target before
promoting them. Never erase the retained old system disk for this project.

```sh
python3 -m unittest discover -s services/3d-printing/tests -v
edsys-3d check
edsys-3d new-project my-project
edsys-3d freecad
edsys-3d blender
edsys-3d cadquery /absolute/path/to/source.py
```

## Post-install Ender KE profile baseline

The current owning guide records the owner-confirmed Ender-3 V3 KE and Zyltech
pink PLA starting recipe. Use the bundled **KE 0.4 mm** printer, not SE/plain V3,
and Orca's **CrealityPrint** host type for the stock interface. Native Test uses
HTTP `/info`; status observation uses TCP 9999. No Moonraker installation,
printer-root access, cloud account, firmware change or hardware-control call
was required. Connection Test does not qualify upload or print delivery.

The three selected user presets include `Uncalibrated` in their names. Their
actual JSON and address-bearing app state stay in isolated Orca user-data;
versioned draft copies live below workspace `printers/ender3-v3-ke` and
`materials/zyltech-pink-pla`. The baseline project's generated outputs remain
in `slicing/NOT-APPROVED`; never use generic installation examples as accepted
machine profiles. Restore only these presets or the private pre-change Orca
state, retaining project data and other apps. Existing durable backup roots
already cover these additions.

For isolated Xvfb GUI verification, a private window manager makes native combo
popups usable. Maximize the app if its initial window requires a layout redraw.
Do not use the real Sunshine desktop as the automated test display. When using
Orca CLI `--outputdir`, give `--export-3mf` a **basename**, not an absolute path:
Orca otherwise prepends the output directory to that absolute path and fails.
Local slice validation must not call Upload or Print.
